# packages/schema

Single source of truth for the resume document shape (design spec §3/§5/§7).

- `resume.schema.json` — JSON Schema 2020-12 (sections, entries, dates,
  personal-details contact chips, layout, sanitizer allowlist version). The
  authoritative contract: every generated type and validator below is derived
  from, or hand-kept in sync with, this file.
- `gen/go/`, `gen/ts/` — **committed** generated types (`resume.go`,
  `resume.ts`), regenerated by `scripts/generate.mjs` (`npm run generate` /
  `make schema-gen`); never hand-edit them, `test/gen.test.ts` fails CI on
  drift. `gen/go/section.go` and `gen/go/store_validate.go` are hand-written
  companions in the same package (see each file's header for why they are not
  generated). `gen/dart/` (Flutter) is deferred — not yet scaffolded.
- `fixtures/*.json` — schema-level conformance fixtures (`test/schema.test.ts`
  asserts every non-`invalid-*` fixture validates and every `invalid-*` fixture
  is rejected). `fixtures/store/*.json` is a separate corpus for the store-layer
  rules below (some are schema-valid clean documents, others are deliberately
  schema-**invalid** hostile documents used to prove the store layer never
  throws/panics on malformed input — see `validation/store.ts`'s header
  comment).
- `validation/store.ts` (TypeScript) and `gen/go/store_validate.go` (Go) — the
  two hand-written halves of the store-layer aggregate validator for rules JSON
  Schema cannot express on its own (byte-accurate rich-text length, the layout
  placement invariant, date-range ordering, and the personal-detail URL-scheme
  check — see `validation/store.ts`'s header for why each exists there instead
  of in `resume.schema.json`). Both are conformance-tested against the same
  `fixtures/{,store/}*.json` corpus (`test/store-validation.test.ts`,
  `gen/go/store_validate_test.go`), so a behavior divergence between the two
  languages fails on both sides, not silently on one.
- `validation/sanitizer-allowlist.v1.json` + `validation/hostile-corpus.json` —
  the versioned rich-text sanitizer allowlist (tags/attributes/URL schemes) and
  the shared XSS payload corpus (design spec §5) that bluemonday (`apps/server`,
  write path) and DOMPurify (`apps/web`, render path) will be conformance-tested
  against once wired — that wiring is P3 (AC-SEC-001); at Phase 0 this package
  only owns the versioned data both will be tested against
  (`test/sanitizer-corpus.test.ts` guards its shape).
- `templates/*.json` — design templates (customization presets): not yet
  scaffolded.
