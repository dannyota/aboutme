# FlowCV → aboutme gap analysis

Every capability in [`feature-inventory.md`](feature-inventory.md) checked
against the aboutme design spec (`docs/specs/aboutme-design.md`) and the frozen
document contract (`packages/schema/resume.schema.json`). Research evidence, not
project authority. Compiled 2026-08-11.

"Changes the frozen contract?" means: would adopting it require editing
`resume.schema.json` (and therefore the generated Go/TS types, store-layer
validation, fixtures and golden snapshots)? Spec §3 Lifecycle allows schema
edits pre-release, so those changes are cheap now and expensive after the first
release — that timing, not the feature's charm, is why the three `v1` rows are
all contract-touching and the merely convenient ones are not.

aboutme is deliberately narrower than FlowCV. "FlowCV has it" is not a reason to
build it, and most rows below are correctly `skip`.

## Where the notes and the aboutme spec disagree

These matter if anyone ever imports a FlowCV document into aboutme.

- **Rich-text alignment is dropped.** FlowCV stores
  `<p style="text-align: justify">` (F27). The aboutme allowlist sets
  `globalAttributes: []` and forbids `style`, so every imported paragraph loses
  its alignment silently.
- **Dates do not survive a naive copy.** FlowCV keeps display strings and a
  `Present` sentinel (F23); aboutme requires `{start:{y,m?}, end, present}` with
  years bounded 1900–2100 and forbids fabricated sentinels, so an import must
  parse and may legitimately fail.
- **Section order lives in different places.** FlowCV keys it per column layout
  inside `customization` (F17); aboutme keys each section exactly once across
  `layout.sections.main` + `sidebar`, enforced as an aggregate invariant. There
  is no lossless mapping when a FlowCV document has different orders for the
  `one` and `two` layouts.
- **Seven FlowCV section types have no aboutme discriminator** (F12). They map
  onto `custom`, which loses the type identity (an `issuer`-style field, for
  example, becomes `subtitle`).
- **Photo shape and source dimensions have nowhere to go** (F56).
- **Internal ambiguity worth resolving in aboutme itself:** spec §1 lists
  section types with a trailing ellipsis ("… project, custom…"), which reads
  open-ended, while §3's table and `resume.schema.json` close the enum at eight.
  The schema is right; the §1 wording invites the wrong expectation.
