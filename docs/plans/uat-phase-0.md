# Phase 0 — UAT acceptance catalog

> **Authored by the integration owner. Immutable during a UAT run.** The UAT
> worker executes this catalog and reports results; it must not edit this file,
> product code, tests, snapshots, seeds, or acceptance criteria. `BLOCKED`
> counts as `FAIL`. See `../../CLAUDE.md` ("Design and delivery workflow") and
> `implementation-plan.md` ("UAT report contract").

Phase 0 ships no product features — no auth, no resumes, no renderer. What it
ships is a **foundation**: contracts that cannot silently drift, a stack that
boots correctly from empty, a route table that sends each path to the right
backend, and quality gates that actually fail when they should. This catalog
tests exactly that, and nothing it does not have.

## Run preconditions

Record before the first scenario and include in the report header: commit SHA
(`git rev-parse HEAD`), `git status --short` (must be clean), Go/Node/podman
versions, container image tags, migration head, and the `.env` fingerprint
(names only — **never values**).

Start from a genuinely empty database:
`podman compose --env-file .env -f deploy/compose.yml down -v` before UAT-1. The
stack publishes on `${CADDY_HTTP_PORT}` (8080 in rootless environments).

## Reporting

One row per ID: expected / observed / `PASS` | `FAIL` | `BLOCKED`, each linked
to its evidence. Missing evidence, an undisclosed retry, or any unexplained
error output fails that row. Report the environment honestly — if a scenario
cannot run here (for example rootless podman cannot bind port 80), mark it
`BLOCKED` with the reason rather than substituting a weaker check.
