# Phase 2B adversarial coverage

Required test coverage for the server lane. Under
[ADR 0024](../../adr/0024-single-pass-delivery-gates.md) the implementing author
writes these cases in the task that owns the behavior; they are no longer
separate tasks with separate authors. Derive each matrix from the written
contracts — `budgets.md`, the schema, the security and API design, and
`docs/api/openapi.yaml` — not from the constants in the implementation.
Transcribing implementation constants defeats the point of a bounds matrix.

Every case runs against the real handler with
`(cd apps/server && REQUIRE_TEST_DB=1 go test ./internal/resumeapi/... -race -count=1)`,
and the concurrency cases repeat at `-count=20`. A case that passes "usually" is
a failure.

## Suite D — auth, CSRF, and cross-user authorization

Owner: Task 4 (write-safety kernel and policies), extended by the route tasks.
File: `apps/server/internal/resumeapi/authz_adversarial_test.go`.

### Cases (add, never subtract)

| Test                                                    | Assert                                                                                                                                                                                                                                                                                                                             |
| ------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `TestEveryRoute_NoSession_401`                          | Enumerate every route from the OpenAPI document (not a transcribed list) and drive each with no cookie: `401 session_required`, no state change, `Cache-Control: no-store`                                                                                                                                                         |
| `TestEveryMutation_CSRFMatrix`                          | For each mutating route: missing token, wrong token, token of the wrong length, correct token with a foreign `Origin`, no `Origin` with a foreign `Referer`, no `Origin` and no `Referer`, and a `Content-Type` of `text/plain` — every one `403 csrf_rejected` with an identical body, and zero database or object-storage deltas |
| `TestMultipartOnlyOnPhotoUpload`                        | `multipart/form-data` is accepted on the upload route and rejected on every other mutating route; conversely a JSON body on the upload route is rejected                                                                                                                                                                           |
| `TestPhotoMethodPoliciesStayDistinct`                   | Owner photo GET is authenticated but CSRF-free; POST uses multipart plus the upload limiter; PATCH crop uses strict JSON plus the ordinary write limiter and no upload permit; DELETE is bodyless. Each wrong media type or missing CSRF case fails before idempotency inspection, database change, or object I/O                  |
| `TestCrossUser_EveryRoute_IndistinguishableFromMissing` | For every per-resume route, user B's request against user A's real id matches a random UUID in status, body, and stable security/cache/content headers. Exclude request-scoped `Date` and `X-Request-Id`; separately require valid distinct request IDs on both responses—no existence oracle (P2A D17)                            |
| `TestCrossUser_NoStateLeak`                             | None of those cross-user attempts changes A's row, revision, `updated_at`, or objects; and none of them consumes a rate-limit budget belonging to A                                                                                                                                                                                |
| `TestSessionRevokedBetweenRequests`                     | A session revoked between two requests makes the second return `401` with no mutation. Mid-request revocation is outside the current contract and is not inferred by this suite                                                                                                                                                    |
| `TestGetSafeMethodsBypassCSRFButNotAuth`                | `GET` routes pass without a CSRF token but still require a session; `HEAD` and `OPTIONS` never mutate                                                                                                                                                                                                                              |
| `TestPathTraversalInRouteParams`                        | `id`, `sectionKey`, and `entryId` values containing `..`, `%2e%2e`, a NUL, a newline, an over-long string, and a non-UUID are rejected with a `400`/`404` from the vocabulary — never a `500`, never a database error surfaced to the client                                                                                       |
| `TestNoRouteAnswers501`                                 | No route returns the Task 4 stub status at the phase head                                                                                                                                                                                                                                                                          |
| `TestErrorBodiesLeakNothing`                            | No error body or header contains a SQL fragment, a stack frame, an object key, a bucket name, an internal host, or another user's identifier                                                                                                                                                                                       |
| `TestStorageSecretsNeverLeak`                           | Configure unique sentinel S3 access-key and secret values, then force startup validation, signing, `Put`, `Get`, and `Delete` failures. Neither sentinel appears in an HTTP response, response header, captured structured log, metric label, panic text, or returned config/backend error                                         |

## Suite E — HTTP write safety and wire version

Owner: Task 2 (transaction seam) and Task 9 (wire version). File:
`apps/server/internal/resumeapi/writesafety_adversarial_test.go`.

| Test                                         | Assert                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `TestIfMatch_ExistingWritesAndCreate`        | Across every existing-resume mutation: missing → `428`; `*`, unquoted, weak (`W/"r1"`), `"1"`, `"r"`, `"r-1"`, `"r 1"`, an enormous number, and a non-numeric revision → `400`; stale → `412`. Create accepts an absent `If-Match` subject to its other inputs and rejects any supplied value with `400 precondition_not_supported`. Every rejection leaves row bytes, `revision`, `updated_at`, and object storage unchanged                                                                                       |

| `TestConcurrentSameRevision_OneWinner`       | N concurrent writers at revision R on the same resume → exactly one `2xx` at R+1 and N−1 `412`s; deterministic under `-race -count=20`; mixed routes (entry, section, structure, customization) in the same race still yield one winner                                                                                                                                                                                                                                                                             |
| `TestIdempotency_ReplayIsByteIdentical`      | Same key and complete D18 identity replays identical status, `Location`/`ETag`/`X-Resume-Schema-Version` where applicable, deterministic Content-Type/cache policy, and body bytes, with no re-execution or second row/object. `Date` and `X-Request-ID` are valid, fresh, and distinct                                                                                                                                                                                                                             |
| `TestIdempotency_BodylessReplay`             | Fresh and replayed resume-delete, entry-delete, and photo-delete responses are 204 with zero body bytes and **no Content-Type header**; internal JSON `null` never appears on the wire. Entry/photo delete preserve identical new-parent `ETag` and schema-version headers; resume delete has neither. Each request hashes a zero-length payload, so an absent versus valid optional JSON Content-Type still replays                                                                                                |
| `TestHeadersAndDeleteBodiesFailClosed`       | Every singleton mutation header rejects repeated field lines and comma folding with its declared code. Ordinary routes may already be read by bounded outer `BodyLimit`, but rejection precedes handler decode, inspection, transaction, and any state change; streaming upload header rejection proves zero body reads. All three DELETE routes accept immediate EOF but reject positive length without a handler read, and reject whitespace, `{}`, chunked bytes, or trailing data before inspection or mutation |
| `TestIdempotency_CanonicalVectors`           | Independently encode and verify D18's six immutable operation/request digest vectors: entry, create, and upload. Exact OpenAPI `operationId` spelling, tuple domain, field names/order, lengths, absence marker, and raw bytes are all covered                                                                                                                                                                                                                                                                      |
| `TestIdempotency_ChangedFingerprintRejected` | Under the same user, canonical operation identity, and key, changing the resolved wire version, parsed precondition, another declared semantic input, or bounded JSON/file bytes returns `409` with zero deltas. Changing only multipart framing or filename still replays                                                                                                                                                                                                                                          |
| `TestIdempotency_ScopedByUserAndOperation`   | The same key used by a different user or a different canonical operation identity—including another concrete target—is a **distinct** mutation and never a cross-target replay                                                                                                                                                                                                                                                                                                                                      |
| `TestIdempotency_ConcurrentSameKey`          | N concurrent identical requests → exactly one mutation commits and the rest replay it; no request observes a partially applied document                                                                                                                                                                                                                                                                                                                                                                             |
| `TestPhotoCrop_WriteSafety`                  | Crop set and null-clear hash their exact JSON bytes, preserve the key read in the CAS transaction, and make zero object calls. Same-key same-bytes replay without another revision; changed bytes return `409`. A crop racing replacement cannot attach to the new key at a stale revision, and successful replacement clears the old crop                                                                                                                                                                          |
| `TestIdempotency_CSRFRetryReusesKey`         | A request rejected with `403 csrf_rejected` and retried with the **same** key and body mutates exactly once — the `../phase-1-deferred.md` forward contract                                                                                                                                                                                                                                                                                                                                                         |
| `TestIdempotency_FailureLeavesNoRecord`      | A mutation rejected at validation, bounds, or CAS leaves no idempotency record, so a corrected retry with the same key succeeds rather than replaying a failure                                                                                                                                                                                                                                                                                                                                                     |
| `TestIdempotency_BoundedRetention`           | From ADR 0016 and budgets, prove 200/201 oldest-first per-user request cleanup, neighbour/unexpired isolation, composite-index plan, exact retained-row/body-plus-header byte counters under concurrency, both retained-capacity boundaries, expired backlog still counted, replay-at-capacity, exact Retry-After branches, and no mutation on new-key rejection                                                                                                                                                    |
| `TestWireVersion_AcceptProjectPersistEmit`   | Against the production current-v2 projector, immutable v1/v2 schemas, and real converters: a v1 entry-upsert route delta down-emits, applies, up-accepts, and persists the **complete v2 document** (assert stored parts and `schema_version`) before emitting v1; write-then-read at v1 loses no representable field                                                                                                                                                                                               |
| `TestWireVersion_FailsClosed`                | Undeclared, non-numeric, negative, zero, and far-future versions → `400 unsupported_schema_version` with no write. A synthetic projector is allowed only to prove unrepresentable registry states such as accept-only versus emit-only                                                                                                                                                                                                                                                                              |
| `TestReadsNeverWrite`                        | Concurrent `GET`s against a row below the current version leave bytes, `revision`, and `updated_at` unchanged (P2A D18 at the HTTP layer)                                                                                                                                                                                                                                                                                                                                                                           |
| `TestRevisionSerializedAsString`             | Every response carrying a revision serializes it as a JSON string, and a revision beyond 2^53 round-trips exactly                                                                                                                                                                                                                                                                                                                                                                                                   |

## Suite F — bounds, hostile payloads, and media

Owner: Task 11 (photo endpoints) for the media cases and Task 5 (sanitizer
boundary) for the hostile-input cases. File:
`apps/server/internal/resumeapi/bounds_adversarial_test.go`. Its gate also needs
`make test-s3-up`, `make server-test-p2b`, and `make server-test-p2b-s3`.

| Test                                  | Assert                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `TestEveryBound_LimitAndLimitPlusOne` | Derive the bound set **independently** from `budgets.md` and the schema — request body 256 KB, document 512 KB, 24 sections, 64 entries/section, 16 KB rich text **in UTF-8 bytes**, 16 details, title 160 code points, `lng` 35, 100 structure commands, and 100 customization deltas — and drive each at the limit and limit+1 through the real handler. A completeness guard fails if a schema bound has no case                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `TestRejectionWritesNothing`          | For every bound/schema/transport rejection above that occurs before object-write dispatch: full-row bytes, `revision`, `updated_at`, row count, and object storage identical before and after. Remote `PutUnknown` is covered separately by `TestMediaOrphans` because object state cannot be known                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `TestByteVsCodePointBounds`           | Rich text of 9,000 `é` characters (18,000 UTF-8 bytes) is rejected even though it is under a code-point limit; a title of 160 astral-plane code points is accepted and 161 rejected                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `TestHostileCorpusThroughHTTP`        | Every payload in the shared hostile corpus written through each rich-text-carrying route is neutralized in the persisted document and in the `GET` response, judged by a predicate this author writes from the allowlist data — **not** by importing P3's `sanitizetest` helper                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `TestPlainTextRoundTripsAsText`       | Markup-looking bytes in free-form plain-text fields such as resume title, section `displayName`, entry title, and personal-details text are accepted when schema-valid and round-trip unchanged in storage and JSON. They are not rich text and P2B must not sanitize or reject them merely for containing markup. P3 owns renderer-context escaping and its separate acceptance proof                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `TestStrictDecode`                    | Malformed JSON, duplicate keys, unknown fields, trailing data, a wrong top-level envelope type, and the depth limit fail as `400 request_invalid`. A syntactically parsed fragment that violates its declared document schema, including `null` for a required non-null field, is `422 document_invalid`. Crop's explicit `{crop:null}` clear is the named exception. Neither class writes state or returns `500`                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `TestMultipartBoundary`               | Independently construct exact request and file byte limits and limit+1, truncated and invalid boundaries, declared-length disagreement, chunked bodies, wrong/missing/duplicate parts, transfer encoding, 255-byte and 256-byte filenames, extra fields, and non-empty epilogues. | `TestImageContainerBoundary`          | JPEG, PNG, lossy/lossless WebP, 16-bit PNG, APNG, animated WebP, malformed lengths, truncation, header/decode dimension disagreement, each terminal marker plus trailing HTML, and legal metadata chunks containing HTML. | `TestImageDimensionsAndPixels`        | Every edge and pixel-product limit and limit+1, including overflow-shaped headers, is checked before full decode and confirmed after it. The frozen release benchmark fails if any accepted boundary or decoder-regression fixture exceeds five seconds or the 192 MiB measured RSS delta                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `TestImageOrientationAndMetadata`     | All Exif orientations 1–8, no tag, malformed/duplicate/conflicting tags, GPS, XMP, IPTC, comments, thumbnails, ICC, and optional chunks. Accepted outputs have correctly oriented pixels and contain none of the source metadata                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `TestCanonicalImageOutput`            | Opaque input becomes deterministic JPEG85 within the 2,048→512 ladder; alpha input becomes deterministic PNG within the 1,024→512 ladder; aspect ratio, no-upscale, canonical type/extension, and the 2 MiB stored-byte ceiling hold. GET returns normalized output, never source bytes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `TestMediaKeyCannotBeInfluenced`      | New keys match only `resumes/{canonical lowercase resume UUID}/photo-{32 lowercase hex}.(jpg\|png)`. No request field, filename, header, input type, or metadata changes the random suffix or normalized-output extension; keys from two uploads differ. Create seeds carrying photo metadata in every accepted wire version fail with `422` and create no row, record, or object. Malformed and cross-resume stored keys never reach Get/Delete; injected collisions use at most three create-only attempts and no loser changes referenced bytes                                                                                                                                                                                                                                                                                              |
| `TestPhotoCropContractAndIsolation`   | Crop set and null-clear enforce the declared version's exact `$defs.photoCrop` shape and bounds, preserve the transaction-read key, use ordinary JSON/write admission, and perform zero object calls. Null removes the property. Replacement always clears the old crop. Crop racing replacement has one CAS winner; stale crop cannot attach to the new key. Replays and reuse follow the exact-body rule without object I/O                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `TestMediaOrphans`                    | Photo replacement, photo delete, and whole-resume delete validate the transaction-read key and commit reference revocation with one exact-key deletion job. Queue failure rolls back both; replay creates no duplicate job. Proved-created candidates compensate after definite database failure; ambiguous database commits do not delete possibly live bytes. A response lost after remote create or collision returns `PutUnknown`, performs no database write, and never deletes that key. A proved-created candidate cannot begin or resume a commit after its five-minute deadline; pause it across that deadline and the 48-hour sweep cutoff and prove a swept key can never become referenced. Invalid/cross-resume keys reach neither queue nor backend. Stable pages preserve age and neighbour isolation for P8-priv reconciliation |
| `TestRateLimitsHold`                  | Read, write, and upload policies each reject over-limit traffic with `429` + `Retry-After`, and one user's traffic cannot exhaust another's budget. | `TestMediaAdmissionAndCleanup`        | A second intake waits at most one second and gets `503` before body read. Read and `Put` have independent cancellable deadlines. Normalization is synchronous and has a measured release gate, not a request timer. Cancellation and every error release the permit; no decoder, goroutine, buffer, or in-process write survives a returned response. A `PutUnknown` private object may remain only as reconciliation-owned stored residual state. The future renderer handoff shares the same permit                                                                                                                                                                                                                                                                                                                                           |
| `TestNoUnboundedWork`                 | Requests with 101 and 10,000 customization deltas, 101 and 10,000 structure commands, or an entry with 10,000 array members are rejected by a declared bound before list application                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
