# Activation decisions, interfaces, and exit criteria

## Activation decisions and inputs

The UAT scope and OpenTofu choice are settled by ADR 0031. This table records
those decisions alongside technical inputs and the Phase 9 cost decision. Only
an unresolved budget or a change beyond the authorized scope needs a new owner
decision; do not ask again for general UAT or DNS permission.

| #   | Item                                                                                                                           | Status or requirement                                                                                                                                                 |
| --- | ------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | D21 sizing and recurring cost                                                                                                  | Phase 9 records a quantified budget and chooses UAT sizing; baseline defaults remain proposed                                                                         |
| 2   | UAT activation scope                                                                                                           | Existing authorization records `uat.aboutme.vn`, `ap-southeast-1`, UAT resources, and Cloudflare DNS; Phase 9 cost decision plus the local checkpoint gate Task 10.15 |
| 3   | AWS account, Cloudflare API token, `var.oncall_email` — human-provided inputs with no acquisition path in-plan                 | Operator supplies them through the approved runtime path after the activation handoff; values never enter this plan                                                   |
| 4   | D1 — OpenTofu toolchain                                                                                                        | Resolve and pin the current stable release at scaffold time; verify provider, mock, state-locking, and write-only feature support before dispatch                     |
| 5   | Web-tier trust posture                                                                                                         | The D24 redesign (web outside the host namespace) remains a proposed baseline for the Phase 7.1/7.2 refresh                                                           |
| 6   | D9 — origin secret unavoidably in CloudFront distribution config + TF state                                                    | Accepted with mitigations: SSE-KMS state + noncurrent expiration, scoped state-read role, rotation runbook                                                            |
| 7   | Public `uat.aboutme.vn` + ACM cert in CT logs while the [trademark gate](../../../design/decisions.md#remaining-gates) is open | Hostname and certificate scope authorized; resolve UAT access/Bearer behavior and noindex, and record certificate-transparency exposure in the inventory              |

## Exit criteria

The distinct local code checkpoint, activation handoff, and hosted-UAT evidence
criteria are maintained in [`exit-criteria.md`](exit-criteria.md). This file
retains the interfaces and constraints that later phases consume; it does not
make hosted UAT a prerequisite for Task 10.15 activation.
