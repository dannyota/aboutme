# Phase 11.1c: privacy notice host fence

State: planned. Start only after Phases 11.1a and 11.1b are integrated and reviewed.

## Objective

Implement the root-owned send and activation authority, cohort-capture marker, restore reconciliation fence, release monotonicity, and hosted proof for the accepted privacy notice. App actions call only the fixed backend command from the current release image. Shared host-only initialize/adopt actions and source-only restore functions require no app image and only establish denial. One fixed host controller owns each complete restore pass. Keep notice sending and changed ingestion disabled after every interruption or restore until explicit owner recovery.

## Required implementation

- Install the fixed root wrapper for app commands from the pinned current release image, plus the shared host-only initialize/adopt primitive and fixed restore-drill host controller in both installer modes before the PostgreSQL-only early return. Implement the design's four zero-argument source-only restore functions, not public pre-restore/postcheck actions. Follow operation-before-workload order and installer bundle serialization. The primitive cannot query the DB, call the app, grant authority, clear reconciliation, accept receipts, or dispatch arbitrary commands; the fixed controller owns DB effects/checks. Do not add an image, app unit, release record, mail key, or Podman dependency to the drill.
- Before fence/authority reads, locks, initialization, mutations, or starts, implement the canonical guest mount preflight and its rechecks. Preserve nofail while refusing absent/ambiguous labels, wrong or shadowed mounts, and identity changes. Prove guest provenance only; neither authenticate a provider volume ID nor infer authority from root-disk shadow state.
- Add notice_restore to the existing fence protocol with the design's exact ownership/admission-tag binding, app-absent admission, start blocking, strict internal notice-restore-release operation, and no db-setup exception. Preserve generic release, existing cutover semantics, minimum floor, and all other operation guards. A stored minimum tag is never a deployed-release or image-start authorization.
- Persist permanent notice_authority evidence in fence.json for every bootstrap/adoption. Implement the reviewed legacy transition under existing cutover/quiesce guards, with durable initializing intent before helper replacement, adopted state only after durable fenced initialization, and exact-operation crash recovery. Preserve evidence on every fence write and reinstall. Missing authority after adoption or missing evidence with post-notice helpers must refuse, not rebootstrap.
- Persist authority only under `/var/lib/aboutme/privacy-notice/` with directory mode 0755 and file mode 0444. Manage a current random UUID `epoch`, `send.json`, `activation.json`, `restore-reconciliation`, and the canonical `capture-in-progress` marker with atomic replacement plus durable file and directory synchronization.
- Mount the authority directory read-only into the server and owner command container. Do not mount individual files or give a container any writable parent or alternate authority path.
- Run owner commands as `aboutme_app` over the Unix socket with `--network=none` and a 256 MiB container memory limit. Only enqueue receives the existing encryption-key secret injection; no command receives SMTP or media credentials.
- Pin receipts to the fixed campaign, compiled content digest, deployed release, cutoff, expected count, current epoch, and issue time as specified. Validate fixed aggregate command output before writing either receipt. Never infer completion from queue emptiness or elapsed time.
- Keep a persistent capture marker from before account-writer shutdown until the exact cohort seals. Interrupted capture keeps maintenance in force and resumes the same campaign under the workload lock.
- Implement exactly the design's host-pass latest/time calls, private _host-pass child, FD 3/4 context/completion grammar, and fixed workload-helper invocation. Reject inputs/overrides outside that contract. Move replacement, recovery, every existing DB check, and authority postcheck into the same locked foreground child; preserve check meanings and the recovery-time measurement. Prove app absence for drill calls and refuse full hosts. Keep the primitive's full-host quiescence branch for separately reviewed controllers.
- Before every cluster/PITR restore, prove send quiescence or app absence, persist reconciliation, rotate epoch, revoke receipts, then replace/start PostgreSQL and recheck denial. Every pass rotates, including explicit retries and the first after bootstrap. Preserve the workload descriptor in foreground restore children through fixed privilege drop, join children/systemd recovery, and require valid private completion plus successful helper join before exact-owner release. No EXIT cleanup, --resume takeover, callback handoff, or later SSH check may clear ownership. Before final release failures retain ownership; at rename/sync or lost-response ambiguity either durable owner outcome is possible, with denial retained and no PASS, rollback, empty-owner release retry, or automatic re-execution. Only a new explicitly requested pass can use an absent owner. Follow the design's crash/SSH recovery and fixed output rules. Restored DB state never clears authority; drills never claim app reconciliation or full-host send/consumer proof.
- Startup, deploy, failed-deploy restoration, rollback, and restore must fail closed on missing or inconsistent state. The monotonic release floor must prevent return to an older notice or worker after activation prerequisites advance.
- Preserve ordinary email when notice sending is fenced. Activation remains impossible until exact accepted-plus-deleted totals and current receipts validate. An irrecoverable active-account failure permanently aborts the campaign and keeps later target-path ingestion disabled.
