# Account localization implementation plan

Status: implementation, four native HTTPS gates, measured phone and desktop
layout checks, and independent review pass. Final verification runs in GitHub CI
under the owner's delegated v0.4.x scope.

**Goal:** Ship Vietnamese and English settings and agent consent without
changing account authority, request payloads, stored values, or pending actions.

**Architecture:** Extend exact route localization, reuse the locale cookie and
`WorkspaceCopy<T>`, and derive component copy from semantic controller states.
Each settings unit owns its catalog. Shared modal language controls use existing
header action slots.

**Tech stack:** Nuxt, Vue, TypeScript, Vitest, Playwright, and native HTTPS.

**Spec:** [Account and agent localization](../design/account-localization.md).

## Global constraints

- The owner requested all v0.4.x releases and delegated review and deployment.
  Independent review, CI, and production checks remain required. Owner UI review
  is not a release gate.
- Follow AGENTS.md. Only the manager performs Git operations or changes runtime
  stacks. Start each task with `git status --short` and preserve others' edits.
- No API, schema, migration, dependency, email, or renderer behavior change.
- Preserve route queries, OAuth scope and decision values, client and account
  identifiers, provider names, request bytes, and the exact `DELETE` token.
- Use existing `Locale`, `aboutme-locale`, `useLocale()`, `useRouteLocale()`,
  `LocaleToggle`, and `WorkspaceCopy<T>` contracts.
- Keep closed semantic error and status values. Render unknown failures with
  safe generic copy. Never show raw server messages.
- Locale changes preserve drafts, focus, selection, selected targets, modal
  identity, pending commands, and fetched data. They trigger no API call.
- Pointer language activation preserves field focus. Keyboard activation keeps
  focus on the activated language button. Never remount a route to translate it.
- Preserve security tests and stable selectors. Use fictional local fixtures.
  Production account checks use only the separately authorized owner account.
- GitHub CI runs builds and test suites. Reuse existing browser evidence. Any
  necessary local diagnostic follows the shared lock and hard memory limit in
  AGENTS.md; do not repeat local gates or restart a stack for duplicate
  evidence.
- Workers report exact paths, red-test evidence, checks and results, and gaps.
  Write plain text, no em dash, and no plan or task IDs in code or living docs.

## Review focus

1. Toggle while password reauthentication or deletion is pending. Fields,
   disabled controls, command count, and target must stay unchanged.
2. Toggle with an unlink or grant-revoke dialog open. The same target and focus
   trap remain; no grant or identity request repeats.
3. Toggle after a failed action. Copy changes immediately while the error kind,
   retry state, and server request count stay unchanged.
4. Toggle consent after loading a hostile client name or a mixed-scope request.
   Render text safely and retain the exact query and decision payload.
5. Open settings or consent with an invalid locale cookie. Use Vietnamese,
   preserve validated return URLs, and keep account catalogs out of other
   routes.

## Interfaces

Catalogs import the existing type rather than adding a parallel framework:

```ts
import type { WorkspaceCopy } from "./workspace";

export const settingsCopy: WorkspaceCopy<SettingsCopy> = {
  vi: {/* explicit typed Vietnamese values */},
  en: {/* explicit typed English values */},
};
```

Each author defines its own complete named catalog type and explicit keys. Copy
functions return plain text. The settings, password, identity, privacy, agent,
and consent catalog export names are respectively `settingsCopy`,
`passwordSettingsCopy`, `identitySettingsCopy`, `privacySettingsCopy`,
`agentSettingsCopy`, and `consentCopy`.

The foundation adds `settings` and `authorize` to `workspaceTitles` in both
locales. Consumers select `workspaceTitles[locale.value].settings` or
`.authorize`. Keep the old `appTitles` export until both consumers migrate, then
remove that unused export within the foundation task.

The user-agent utility accepts an optional presentation object while retaining
English behavior for existing callers:

```ts
export interface UserAgentCopy {
  readonly unknown: string;
  readonly on: (browser: string, system: string) => string;
}
export function describeUserAgent(ua: string, copy?: UserAgentCopy): string;
```

Parsing bounds and recognized names stay unchanged. The settings catalog
supplies localized `unknown` and `on` values. Relative time uses its existing
locale argument. Identity and grant dates remain UTC with locale-specific
display.

## Author sequence

The six frontend slices may run in parallel because their owned files differ.
Each author follows this sequence within its slice:

- [ ] Read the spec and current component, controllers, and owned tests.
- [ ] Add a failing test for Vietnamese rendering and a locale change while the
      unit retains meaningful state. Observe the expected assertion failure.
- [ ] Add complete typed catalogs and reactive copy selection. Convert stored
      display messages to semantic codes only where necessary.
- [ ] Keep existing English assertions by explicitly selecting English with
      `setSiteLocale('en')` from `test/support/locale.ts`. Add independent
      Vietnamese assertions, not translated versions of every existing test.
- [ ] Test unknown failures and preservation of request counts, drafts, targets,
      selected values, pending state, focus, and dialog identity as applicable.
- [ ] Run the owned Vitest files and scoped ESLint. Report exact paths and
      checks.

A component regression uses the existing reactive state, not a remount:

```ts
const locale = useState<"vi" | "en">("aboutme-locale");
locale.value = "vi";
await nextTick();
expect(wrapper.text()).toContain("Mật khẩu");
expect(actions.setPassword).not.toHaveBeenCalled();
```

Use actual existing action spies and selectors in each test. Password controls
also retain draft values. Privacy retains `DELETE`. Identity and grant dialogs
retain target identity. Consent records one initial load and zero duplicate
consent decisions during language changes.

The foundation author first proves exact route classification and title parity.
After other authors finish, it checks all six catalogs for key parity and scans
covered visible and accessibility strings. It adds a transitive import check
that rejects account or consent catalogs in public render, print, landing,
gallery, auth, or editor roots. Guard tests include a negative fixture so the
check cannot pass by checking an empty file set.
